# 能力边界

一句话：**把一页图片变成按阅读顺序排列的 Markdown**，全程在设备上完成，不保存、不上传、不做项目管理。

## 1. 适用场景

- 现场用手机拍一页文献 / 扫描稿，想知道它能被识别成什么；
- 验证「版面分析 + VLM 两阶段」在端侧的效果与耗时；
- 作为后续移动端功能的参照实现（可复制的最小骨架）。

不适用于：批量建档、校对工作流、导出交付——那些在主项目的 Web 端。

## 2. 输入能力

| 项 | 边界 |
|---|---|
| 图片格式 | iOS：`UIImage` 能解码的格式（HEIC / JPEG / PNG / TIFF…）；Android：`BitmapFactory` 支持的格式 |
| 来源 | 相机拍照（单张）、相册多选（≤20 张）、文件选择（单张） |
| 方向 | 用 EXIF 方向自动纠正（Android 显式旋转，iOS 用渲染归一化） |
| 尺寸 | 进核心前整页限制 **1200 万像素**（等比降采样），单块再限制 **1,003,520 像素** |
| 语言 | 阿拉伯语 / 波斯语 / 普什图语等 109 种语言共用同一套 VL 权重（官方能力），demo 未做语言选择 |
| 多页 PDF | **不支持**，只能逐页转成图片后选图 |

## 3. 输出能力

| 项 | 说明 |
|---|---|
| 版面块 | 25 类标签之一（`text` / `doc_title` / `table` / `display_formula` / `image` …）+ 原图像素坐标 + 阅读顺序号 |
| 阅读顺序 | 版面模型输出的 order 键升序；官方跳过的 11 类（插图 / 页眉页脚 / 脚注 / 旁注等）不编号（`-1`），排在最后 |
| Markdown | 按阅读顺序合并；`doc_title` → `#`、`paragraph_title` → `##`、正文原样、插图输出 `![](block-N)` 占位 |
| 表格 | **OTSL 原文**（未转 HTML） |
| 公式 | **LaTeX 原文**（保留 `\(...\)`，未转 `$...$`） |
| 进度 | 逐块进度 `k / n`，附带单页耗时 |
| 置信度 | **不提供**。VLM 是自回归生成，没有 token 级置信度，界面显示「已识别」而不是分数 |

## 4. 明确不支持

| 能力 | 原因 / 替代 |
|---|---|
| 保存 / 项目 / 文档 / 版本 | demo 范围外，结果在页面退出后丢弃 |
| 校对 / 行级编辑 / 低置信度跳转 | 同上；且 VL 线没有行级置信度 |
| 导出（docx / searchable PDF / txt） | 主项目 Web 端能力 |
| 多页 PDF 直接输入 | 需要渲染层，demo 只收图片 |
| 方向分类 / 弯曲矫正 | 预设默认关闭（`doc_orientation_classify=false`、`doc_unwarping=false`） |
| 图表 / 印章专项识别 | 预设默认关闭，这两类块退化为「插图」 |
| 表格 OTSL → HTML、公式 → `$…$` | 官方产线后处理，demo 未移植（原文保留，信息不丢） |
| 行级 / 词级坐标 | VL 线以「版面块」为粒度，不产出文本行框 |
| 批量队列 / 断点续跑 / 指纹缓存 | 单机一次性识别，没有 Job 概念 |
| 并发识别 | 逐页串行、逐块串行（端侧内存所限） |

## 5. 精度边界

- 版面阈值固定 `score ≥ 0.4`，同类 NMS `0.6`、异类 `0.98`、最多 100 个框；
  这是**整页标定**的结果，窄图或纯色块上会漏检/误检。
- 整页被误判成一张插图时会被丢弃（横版面积占比 > 0.82、竖版 > 0.93）。
- 插图类（`image` / `header_image` / `footer_image`）**默认不送 VLM**，Markdown 里只有占位符；
  这是官方为了控制耗时与幻觉的默认行为。
- 单块失败不会拖垮整页：该块标记为「未识别」，其余块正常输出。
- 表格密集页容易出现 OTSL 断裂或重复，属于模型行为，不是渲染问题。

## 6. 性能边界

| 项 | 现状 |
|---|---|
| 模型 | 版面 PP-DocLayoutV3（800×800）+ PaddleOCR-VL-1.6 0.9B（GGUF） |
| 单页耗时 | 数十秒量级，**随版面块数量线性增长**（逐块串行） |
| 首次调用 | 模型加载 + warmup 数秒到十几秒，之后常驻 |
| 上下文 | `n_ctx=8192`、`n_batch=2048`、单块视觉 token 上限 2048、生成长度上限 2048 |
| 内存 | 8 GB 机型余量不大；整页已限制 1200 万像素 |
| Android ABI | 只编译 `arm64-v8a` |

## 7. 数据与隐私边界

- 默认**全程离线**：图片、识别结果都不出设备，无账号、无遥测、无日志上报。
- 唯一会出网的是设置里的「远程服务」调试模式（指向内网 `http://…/v1`，Info.plist 已开 ATS 例外）。
- 模型文件放在 App 私有目录（iOS `Documents/Models/`，Android `files/models/`），卸载即删。
- 相机 / 相册权限只用于取图；不写系统相册、不申请通讯录/定位等无关权限。

## 8. 平台与依赖边界

| 项 | iOS | Android |
|---|---|---|
| 系统 | iOS 17+，arm64 真机 | minSdk 26（8.0）+，arm64-v8a |
| 版面引擎 | `onnxruntime.xcframework`（C API，静态） | `onnxruntime-android` AAR 的 headers + `libonnxruntime.so` |
| VLM 引擎 | `llama.xcframework`（含 libmtmd） | llama.cpp 源码，NDK 编译 |
| 安装方式 | 未签名 ipa → Sideloadly 重签 | `adb install` / Android Studio |

模型必须**成对**：`pipeline_version = v1.6` ↔ `PP-DocLayoutV3` + `PaddleOCR-VL-1.6`。
配套关系错了不会报错，只会静默劣化版面精度，因此两端都在启动时校验。

## 9. 与主项目 VL 线的一致性

**完全一致**（同一份规则，`impl/shard`）：

- 25 类标签字典与 `RegionType` 映射
- 跳过阅读顺序的 11 类、不写 Markdown 的 7 类
- 官方提示词文本（`OCR:` / `Table Recognition:` / `Formula Recognition:` / `Chart` / `Seal`）
- 阅读顺序编号规则与并列键处理
- `max_new_tokens = 2048`、产线 `v1.6`、版面框形状 `auto`

**demo 简化**（不追求对齐）：

- 表格不转 HTML、公式不转 `$…$`、无方向分类/去弯曲/图表/印章
- 无三线程流水线（`use_queues`）、无指纹缓存、无落库与两段提交
- 版面框统一按外接矩形裁剪（不做 quad/poly 透视矫正）
