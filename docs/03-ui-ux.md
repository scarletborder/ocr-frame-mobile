# UI / UX 设计稿

目标：**一个动作**（选一张图）→ **一个结果**（整页 Markdown）。没有导航层级、没有配置台、没有第二步。

## 1. 设计原则

| 原则 | 落地 |
|---|---|
| 单任务 | 只有两个 tab：识别、设置。识别页首屏就能完成全部操作 |
| 零层级 | 结果直接进详情，没有中间页、没有二次确认 |
| 过程可见 | 逐块进度（`k/n`）而不是转圈，让用户知道「慢在哪」 |
| 失败可行动 | 错误文案写清「缺什么、去哪补」，不暴露错误码与堆栈 |
| 端侧可信 | 界面明确「模型已就绪 / 未就绪」，不让用户点了才发现没模型 |

## 2. 信息架构

```
App
├── 识别（默认 tab）
│   ├── 状态卡（模型是否就绪 / 预设 / 运行方式）
│   ├── 拍摄识别（主按钮）
│   ├── 相册多选 / 文件选择（次按钮）
│   ├── 错误提示（按需）
│   └── 结果列表 ──▶ 结果详情
│                      ├── Markdown
│                      └── 版面块（标签 / 顺序 / 文本）
└── 设置
    ├── 预设（只读：名称、产线、生成长度）
    ├── 模型（版面 / VLM / 视觉投影器 / 重新扫描）
    ├── 运行方式（本地 / 远程 + 服务地址）
    ├── 引擎（两行：已链接 / 未链接）
    └── 关于（范围声明）
```

三个开关的语义与 PC 文档页同名选项对齐：

| 开关 | 画什么 | 说明 |

## 4. 组件规格

| 组件 | 规格 |
|---|---|
| 主按钮（拍摄） | 圆形 200×200；渐变 `primary → primary@0.72`；阴影 y=8 blur=16 opacity 0.3；图标 42，文案 17 SemiBold；识别中透明度 0.5 且不可点 |
| 次入口 | 高度 48（padding 14 + 内容）；圆角 14；图标 18 + 文案 15 Medium；两列等宽，间距 12 |
| 卡片 | 圆角 16；内边距 16；背景 `secondarySystemGroupedBackground`（iOS）/ `surface`（Android） |
| 缩略图 | 56×72，圆角 8，`scaledToFill` |
| 状态卡 | 标题 17 SemiBold + 两行 15 次要色；就绪绿 `#2E7D32`，未就绪橙 `#E65100` |
| 错误条 | 背景红 8%，文字 `#B3261E` 13pt，圆角 12，内边距 12 |
| 结果正文 | 17pt / 行距 30（≈1.76）；版面块正文 16pt / 行距 26 |
| 标签胶囊 | 11pt SemiBold；水平 8 / 垂直 3；主色 12% 底 |
| 页面间距 | 主间距 16；组内 12；紧凑 8；文本行 4 |
| 点击区域 | iOS ≥44pt，Android ≥48dp |
| 主题色 | iOS 系统 accent（默认蓝）；Android `#2F6BFF` |

## 5. 状态矩阵（识别页）

| 状态 | 状态卡 | 主按钮 | 列表 | 其它 |
|---|---|---|---|---|
| 模型未就绪 | ⚠ 橙色 + 引导到设置 | 可点（点后报错说明缺什么） | 空 | — |
| 就绪 · 空 | ✓ 绿色 | 可点 | 空 | — |
| 识别中 | 不变 | 禁用 + 半透明 | 逐行推进度 | 「清空」禁用 |
| 单页成功 | 不变 | 可点 | 「12.4 秒 · 9 个块」+ `›` | 可进详情 |
| 单页失败 | 不变 | 可点 | 红图标 + 原因 | 可重拍 |
| 引擎未编译 | 未就绪 | 可点 | — | 错误文案指出「该构建不含 xx 引擎」 |
| 远程不可达 | 就绪 | 可点 | 每块失败或整页失败 | 红框带 HTTP 状态码 |

## 6. 交互流程

**相机**：点主按钮 → 有权限直接开相机；无权限先弹系统授权 → 拒绝后红框提示去系统设置。
拍完立即开始识别，不回到列表再确认。

**相册**：点「从相册」→ 系统多选（≤20）→ 选完立即识别；解码失败的图会被跳过，全部失败时红框。

**文件**：点「从文件」→ 系统文件选择器（图片）→ 选一张 → 识别。

**结果**：点任意「识别完成」的行进入详情；详情顶部返回回到列表；详情不提供编辑。

**设置**：点模型行 → 系统文件选择器 → 复制进 App 目录并回填；行内左滑（iOS）/ 重选（Android）可清除。

**清空**：只在非识别中可用，清空列表与错误。

## 7. 排版与 RTL（最高优先级）

- 文本一律按**逻辑顺序**存储与渲染，任何地方都不做 `reverse()`、不按视觉顺序重排。
- 阿拉伯文 / 波斯文 / 普什图文：字号 ≥17、行距 ≈2.0、**禁用 letter-spacing**、禁用 text-transform。
- 界面文案是中文（LTR），但结果区内容是 RTL：容器不强制 `dir`，交给系统 bidi 算法。
- 混排数字/拉丁片段由文本引擎自动隔离；需要显式隔离时用 `<bdi>`（iOS `Text` 与 Compose `Text` 均已正确处理）。
- 复制出去的顺序必须正确 —— 这是 P0 验收项（在结果页全选复制到记事本检查）。

## 8. 文案规范

- 错误必须「可读 + 可行动」：说清缺什么、去哪补，例：
  - ✅「请先在「设置」里选择版面分析模型。」
  - ✅「当前构建未链接 llama.xcframework（含 libmtmd）。请先运行 scripts/bootstrap.sh，或改用远程服务模式。」
  - ❌「Error -1」「OCR_E_VL_PARSE_FAILED」
- 不向最终用户暴露阈值、`batch_size`、CUDA 等工程概念。
- 设置页会显示模型**文件名**：这是管理员「主动选择并替换模型」的场景，属于主项目 AGENTS §6.4 的模型管理例外；
  预设列表、普通表单仍不展示代号与参数。

## 9. 可访问性

- 前景/背景对比度 ≥ 4.5:1；主按钮白字在渐变上均达标。
- 图标按钮均带语义标签（iOS `Label` / Android `contentDescription`）。
- 点击区域 ≥44pt / 48dp。
- **已知限制**：结果正文用固定 17pt，未接 Dynamic Type / 系统字体缩放（RTL 排版对行高的要求优先）。

## 10. 两端差异（有意为之）

| 项 | iOS | Android |
|---|---|---|
| 设置页容器 | 系统 `List` 分组 | `Card` 堆叠 |
| 分段控件 | `Picker(.segmented)` | `TabRow` |
| 主题色 | 系统 accent | `#2F6BFF` |
| 模型收纳 | 自动扫 `Documents` 根目录 | 无（SAF 选择器直接复制进 `files/models`） |
| 底部导航 | `TabView` | `NavigationBar` |

除上表外，两端的层级、文案、间距与状态完全一致——因为 VL 线规则和结果结构都来自同一份 `impl/shard`。
